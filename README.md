# Cascade

Turns GitHub issues into test-verified draft patches with a team of agents, and learns which model
and reasoning effort to use per issue. The thesis: a cost-aware router can match an always-max-effort
baseline's resolve rate at materially lower cost per resolved issue. A null result is an acceptable
outcome; a fabricated or leaky one is not. Project rules are in `CLAUDE.md`, the design in
`docs/SPEC.md`, the evaluation plan (committed before the test split was used) in
`docs/EVAL_PLAN.md`, and every non-obvious choice in `DECISIONS.md`.

Cascade drafts; it never opens a pull request. The live pilot (`cascade draft`) writes a patch and
PR text, with an AI-assistance disclosure, for a human to review and submit.

## Architecture

```
GitHub PRs ──► taskgen ──► tasks/manifest.jsonl ──► audit (human) ──► frozen repo-level split
                                   │
                  harness: sandbox · ledger · providers (mock | openai)
                                   │
   issue ─► Triager ─► Reproducer ─► Localizer ─► Patcher ─► Reviewer ─► Verifier (no LLM)
                                   │
           outcome matrix: task × arm  →  { true_success, verifier_claimed, cost, tokens }
                                   │
       routing policies replayed offline: fixed · cascade · oracle · predictive (LORO-CV, train only)
                                   │
              evals: paired bootstrap · non-inferiority headline · ablations · Verifier FP/FN
                                   │
                    one guarded final run on the test split ─► results/final + FINAL.lock.json
```

- **Task pipeline** (`cascade/taskgen`): mines merged PRs that close issues, inside a date window
  after every arm's knowledge cutoff; builds a per-repo Docker image; keeps a task only if its tests
  fail before the fix and pass after, three times in a row. Attrition is reported per stage. Only
  human-audited-ok tasks enter an experiment.
- **Harness** (`cascade/harness`): network-off Docker sandboxes, a leak guard over every mount, a
  SQLite ledger of every model call with global, per-task, per-attempt, and per-bucket dollar caps, a
  kill-switch file, and a mock provider (the default, $0). Real spend needs `CASCADE_ALLOW_SPEND=1`.
- **Agents** (`cascade/agents`): six roles on the OpenAI Agents SDK with deterministic tools
  (ripgrep/BM25 search, an edit tool, a pytest runner). The Verifier calls no model: it runs the
  agent's reproducer and the repo's visible tests. Two outcomes per attempt: `true_success` (hidden
  tests pass) and `verifier_claimed` (the pipeline's own evidence).
- **Routing and evals** (`cascade/routing`, `cascade/evals`): the matrix runner is resumable and
  idempotent; policies are lookups in the cached matrix, so any policy is replayed at no cost. The
  headline is a non-inferiority test on resolve rate against always-max plus a cost reduction, with
  10,000-resample paired-bootstrap intervals. The test split is touched once, by `cascade eval
  --final`, which refuses to run unless the plan is committed, the tree is clean, and no lock exists.
- **Live pilot** (`cascade/pilot`): read-only issue access, an allow-list of owned or opt-in repos,
  drafts only, spend capped by the `live_pilot` bucket and tagged `purpose=live_pilot`.

## Reproduce from a clean clone

Needs Python 3.11+, [uv](https://docs.astral.sh/uv/), and Docker. Everything up to the real runs
costs $0 and works on the mock provider.

```bash
git clone <this repo> && cd Cascade
uv sync --locked
make check                     # ruff, pyright, pytest
make smoke                     # end-to-end on the synthetic fixture, mock provider, $0
uv run cascade config-status   # lists every TODO you still have to fill in configs/*.yaml
cp .env.example .env           # then set GITHUB_TOKEN (read-only); never commit .env
```

Fill `configs/models.yaml` (model names, prices, knowledge cutoffs), `configs/repos.yaml` (repos,
install/test commands, date window), and `configs/budget.yaml` (dollar caps, including a
`live_pilot` bucket). Prices and caps are yours to fill from the provider's page; nothing is
defaulted. Then, in order:

```bash
uv run cascade taskgen run-all                  # mine, filter, build images, validate ($0)
uv run cascade split freeze                     # freeze the repo-level train/test split
uv run cascade audit review                     # human audit; only audited-ok tasks are used
uv run cascade tasks finalize
uv run cascade preflight                        # leakage check, no spend
uv run cascade pilot --provider openai          # first real spend: a small stratified train pilot
uv run cascade size && uv run cascade calibrate # size the matrix, check the Verifier on the pilot
uv run cascade matrix run --provider openai     # the full outcome matrix (resumable)
uv run cascade ablate --provider openai
uv run cascade repeat-subset --provider openai
uv run cascade export                           # parquet: runs/export/{matrix,ledger}.parquet
uv run cascade eval                             # dev analysis: train/CV only
git tag -a eval-plan-v1 -m "evaluation plan confirmed"   # after you have read docs/EVAL_PLAN.md
uv run cascade eval --final                     # ONCE: writes results/final and FINAL.lock.json
```

The live pilot, after the final evaluation (list owned or opt-in repos under `pilot_repos` in
`configs/repos.yaml` first):

```bash
uv run cascade draft --repo owner/name --issue 123   # draft only; default policy = the one the final eval designated
uv run cascade review --repo owner/name --issue 123 --outcome minor_edits --lines-edited 4
uv run cascade pilot-metrics
```

Resume numbers, README results, and write-up, all generated from artifacts and failing loudly if one
is missing:

```bash
uv run cascade resume-stats                         # artifacts/resume_stats.json
uv run cascade resume-bullets                       # docs/resume_bullets.md, with character counts
uv run python scripts/make_readme_results.py        # the results block above
uv run python scripts/make_writeup.py               # docs/WRITEUP.md
```

## Limitations

Read these with the numbers in the results section; they are why none of it is a guarantee.

- **Contamination risk.** An arm may have seen a repo, or even a later fix, in training. The task
  window starts after every arm's knowledge cutoff to reduce this, but cannot rule it out. Each
  arm's cutoff and the task window are listed in the generated results section ("Facts the
  limitations refer to").
- **One run per matrix cell.** Every (task, arm) outcome is a single sample of a stochastic system.
  The repeat-subset analysis estimates how often a cell flips on a second seed; that noise estimate
  is in the generated results section, and every interval reflects sampling over tasks, not
  within-cell variance.
- **The cascade independence assumption.** The cascade policy is replayed from stand-alone cell
  outcomes, as if a later arm's run were unaffected by an earlier failed attempt. A real cascade
  could pass the failed patch or the Verifier's findings forward, which could help or hurt.
- **Verifier false positives.** A patch the Verifier believes but the hidden tests reject stops the
  cascade early and counts as a failure. The false-positive rate in the results section bounds how
  much the cascade can save.
- **Wide intervals on a small test split.** Whole repos are held out, so the test split is small and
  clustered by repo. The margin for the non-inferiority test follows a rule fixed in advance in
  `docs/EVAL_PLAN.md`; when the data cannot resolve the claim, the verdict is INCONCLUSIVE and is
  reported as such, not softened.
- **The pilot covers only owned or opt-in repos.** It has 5-10 issues, reviewed by the author, and
  is not a sample of open-source issues in general. Cascade itself never pushes, opens a PR, or
  comments; accepted drafts are submitted by a human, with disclosure.
