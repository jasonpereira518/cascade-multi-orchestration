## The question

Cascade turns GitHub issues into test-verified draft patches with a team of agents (triage,
reproduce, localize, patch, review, verify). Its model and reasoning effort can be chosen per issue.
The hypothesis: a cost-aware router can match the resolve rate of always running the strongest,
most expensive setting at a materially lower cost per resolved issue. A null result is an
acceptable outcome; the plan in `docs/EVAL_PLAN.md` was committed before the test split was used.

## Method

1. Tasks are merged PRs from the configured repos, restricted to a window after every arm's
   knowledge cutoff, with the fix hidden and its tests used only for grading. Each task was audited
   by a human. The train/test split is frozen by hash and by repo.
2. Every arm (model plus effort) ran every task once, in network-off Docker sandboxes, producing an
   outcome matrix: hidden-test result, the Verifier's own verdict, and cost from the ledger.
3. Routing policies (fixed arms, a cascade that escalates when the Verifier is unconvinced, an
   oracle with hindsight, and learned routers) are replayed offline from that matrix, so every policy
   is compared on identical outcomes. Routers are fitted on the train split only.
4. The headline is a non-inferiority test on resolve rate against always-max, paired with a cost
   comparison, with paired-bootstrap intervals.

## Limitations

The numbers these refer to are generated here, not typed:

{{FACTS}}

- **Contamination.** Arms may have seen the repos before their cutoff; the task window is chosen to
  fall after it, but a model can still know a project's style or a later fix from outside its
  stated training data. Nothing here proves otherwise.
- **One run per cell.** Each matrix cell is a single sample of a stochastic system.
- **Cascade independence.** The cascade is replayed as if each arm's run were independent of the
  earlier failed attempt; a real cascade could pass information forward.
- **Verifier false positives.** A patch the Verifier believes but the hidden tests reject stops the
  cascade early and counts as a failure; the table above bounds how much that matters.
- **Small test split.** Intervals are wide; an inconclusive verdict is a real outcome.
- **The pilot** covers only repos the author owns or whose maintainers opted in, and drafts were
  reviewed by the author; it is not an unbiased sample of issues.
